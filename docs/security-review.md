# Phase 8 — Security review and residual risks

## Changes verified in this phase

- Admin document endpoints reject an unset or default `change-me` key and use
  constant-time comparison for the configured shared key.
- Upload names are reduced to a basename after normalizing both POSIX and
  Windows path separators. Stored paths remain UUID-generated by the registry.
- Upload size and extension are bounded; TXT/Markdown encoding and PDF/DOCX
  signatures are validated by the registry before document loaders run.
- `effective_date` accepts only the `YYYY-MM-DD` form and a valid calendar date.
- Review labels are constrained to `CONTRADICTION`, `CONSISTENT` or `UNCERTAIN`;
  whitespace-only reviewer identifiers are rejected.
- Failed, duplicate and completed ingestion events are recorded without storing
  document bodies in the document audit details.
- API responses receive `Cache-Control: no-store`; all responses receive
  `nosniff`, frame-denial, referrer, permissions and restrictive same-origin CSP
  headers. The current HTML template uses external same-origin CSS/JS files and
  is compatible with this CSP.
- Chat and admin endpoint errors return generic messages rather than raw
  exception details. Server logs may contain exception details for operators.
- Historical document files, versions and Pinecone vectors are not purged by
  comparison, verification, review or retirement.

## Residual risks before internet-facing deployment

| Risk | Severity | Current status / required mitigation |
|---|---|---|
| Shared admin API key is not an identity provider | High | Suitable only for controlled demo/internal pilot. Use SSO/OIDC, role-based authorization, per-user identity and key rotation before production. |
| `/api/chat` has no authentication or rate limit | High | Add enterprise identity and per-user/IP quotas at the application or trusted gateway before exposing it beyond a controlled network. |
| TLS and trusted reverse-proxy configuration are external | High | Terminate TLS at a managed proxy; restrict direct app-port access. Configure trusted hosts and forwarded headers for the chosen deployment. |
| Multipart parsing may buffer request bodies before endpoint-level file-size validation | Medium | Enforce request-body limits at the reverse proxy/load balancer and use streaming upload controls for large-scale deployment. |
| Uploaded PDF/DOCX files are parsed without antivirus scanning or parser sandboxing | High | Add malware scanning, isolated parsing workers, CPU/memory/time limits and quarantine before accepting untrusted external uploads. |
| No per-document or tenant-level authorization model | High | Add tenant/document ACL metadata and enforce it in listing, retrieval, comparison and verification before multi-tenant use. |
| No persistent rate limiting or abuse monitoring for ANN runs | Medium | Add quotas, concurrency limits, job queueing and operational metrics before high-volume use. |
| Reviewer identity is a supplied audit string behind the shared admin key | High | Bind reviewer identity to authenticated SSO claims; do not treat the request's reviewer field as proof of identity. |
| ANN labels come from a small engineer-curated seed dataset | High | Require an independently human-reviewed, representative domain test set and independent model validation before policy-impacting use. |
| Live OpenAI/Pinecone/Tavily integration was not available in this build environment | High | Complete the credentialed deployment smoke test and validate provider versions, index dimensions, namespace filters and fallback behaviour. |

## Deployment boundary

This review is a code-level development review, not a penetration test, security
certification, privacy assessment or production approval. The system must not
be deployed to the public internet or used as the authority for policy decisions
until the residual high-severity items are addressed and reviewed by the
organization's security and platform owners.
